## Slide 3: v2 現狀問題與核心痛點 (v2 Bottlenecks)

### **為何 v2 必須進行徹底重構？**

1. **嚴重的評測集資料洩漏 (Data Leakage)**
   - 15,450 句評測集中，高達 **13,978 句（90.5%）被 v2 訓練集覆蓋**，先前的評測分數為過擬合記憶假象。
2. **Tokenizer 缺陷導致 `<unk>` 截斷**
   - 缺少 Byte-fallback：雖僅佔字元 0.32%，但影響 **23% 華語句子**（如「猴、蕉、橘」及族語喉塞音 `'`）。
3. **重複詞崩塌 (Repetition Collapse)**
   - 族語疊詞（如 `fafoy, fafoy, fafoy`）在解碼端被過度去重坍縮為單一詞彙（「豬」）。
4. **大小寫與 ASR 轉寫標記混亂**
   - 書寫體首字大寫與 ASR 小寫文本衝突，缺乏統一前/後處理機制。

## Slide 4: v3 系統架構與資料前處理管線 (Pipeline)

### **資料工程與訓練架構升級**

```mermaid
flowchart LR
    A[10 組原始平行語料] --> B[prepare_data.py<br>除污/去重/大小寫正規化]
    B --> C[擴充 Tokenizer<br>Byte-Fallback + 42 方言 Token]
    C --> D[4x A5000 訓練<br>BatchRebalanceSampler]
    D --> E[v3 旗艦模型<br>120 萬雙向句對]
```

- **Tokenizer 升級**：追加 256 個 Byte Token，達成 **0% `<unk>`**；新增 42 個方言代碼標記。
- **大小寫精確控制**：
  - 一般方言：訓練前置小寫化，推論後處理還原首字大寫。
  - **音位對立方言**：噶瑪蘭語（`ckv_Kava`）、賽夏語（`xsy_Sais`）大小寫具音位意義，**完全保留大小寫**。
- **動態負載平衡**：`BatchRebalanceSampler` 依 token 運算量動態均分 4 張 GPU，大幅降低 padding 浪費。

## Slide 7: 消融實驗 1 — 弱對齊新聞語料 (Formosan News)

### **大意編譯的新聞語料是否該加入？**

- **測試設定**：針對 `formosan_news`（族語新聞語料，4.3 萬筆）測試兩種方案：
  - **篩選單向**：模型過濾高對齊度語句，僅加入「華語→族語」（16,474 筆）
  - **不篩選雙向**：全量直接納入訓練（43,724 筆）

| 評測項目 (chrF / BLEU) | v3 (基準線) | 新聞 (篩選，單向) | 新聞 (不篩選，雙向) |
|---|:---:|:---:|:---:|
| **v2-unseen 族語→華語** | **81.97 / 83.31** | 81.07 / 82.64 | 80.18 / 81.73（顯著衰退） |
| **v2-unseen 華語→族語** | **55.84 / 30.83** | **55.92** / 29.72 | 55.80 / 29.58 |
| **段落 華語→族語** | 39.40 / 9.54 | **40.09 / 10.14** | 39.87 / 9.38 |

### **結論：整體弊大於利**
- **多譯與漏譯**：未對齊新聞使模型學會「無中生有」，族語→華語全面衰退（−1.8 chrF）。
- **決策**：**主線版本不予採用**；僅在極度追求華語→族語段落多樣性時，可保守納入篩選單向資料。

## Slide 8: 消融實驗 2 — 詞彙注入與拼接長句

### **單純增加詞彙量與人為拉長句子有用嗎？**

- **詞彙組 (Words)**：回補 15.6 萬筆 `klokah`（族語E樂園教材）單詞表（`*_word`）。
- **串接段落組 (Concat)**：連續 2～4 句硬拼接成 11.7 萬筆長句資料。

```
[實驗評估: 相較於 v3 基準線之差值]
• 詞彙組 (Words)   ── 各項指標普遍微幅下降 0.2 ~ 0.5 (語法連貫性受損)
• 串接組 (Concat)  ── 段落翻譯未提升，v2-unseen 族語→華語重挫 -2.84 chrF!
```

### **原因剖析與技術決策**
1. **單詞表缺乏上下文**：孤立的詞彙映射破壞了解碼器的語言模型（LM Prior）。
2. **串接文體失真**：逗號硬拼接與真實段落文體不符，且長句霸佔 attention 計算，稀釋短句梯度。
3. **決策**：**雙雙否決，維持 v3 純淨句子結構。**

## Slide 9: 消融實驗 3 — 11 方言多工詞素標注

### **引入語言學切分與詞素註解的交互影響**

聚焦 11 方言，探討四種層次：`c` (基準) → `b` (+原句) → `a` (+`<seg>`切分) → `d` (+`<gloss>`詞素翻譯)。

```
全語料 v3 基準: 84.93 / 86.51
      │ (限縮至 11 方言)
      ▼
純 11 方言組 c : 74.70 / 77.60 ───► 重挫 -10.23 chrF！(證實跨方言遷移極度重要)
      │ (+ 詞素標注 a/b/d)
      ▼
標注組別 a/b/d : 74.05 ~ 74.47 ───► 常規翻譯指標微降 0.1 ~ 0.8
```

### **關鍵發現**
1. **多工格式控制成功習得**：輸入 `<seg>` 輸出詞素邊界（`ma-`、`=ku`），輸入 `<gloss>` 輸出詞素對齊。
2. **表徵共享是生命線**：跨方言聯合訓練大幅補足低資源語言之泛化性，**不可單獨將各方言切開微調**。
