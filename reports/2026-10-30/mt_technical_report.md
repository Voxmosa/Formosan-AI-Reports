# 臺灣原住民族語機器翻譯 (Formosan MT) v3 模型技術研發報告

**報告日期**：2026 年 10 月 30 日  
**專案代號**：Formosan-NLLB-v3  
**基底架構**：Meta NLLB-200 (`facebook/nllb-200-distilled-600M`)  
**報告性質**：技術架構、資料工程與消融實驗評估報告  

---

## 1. 執行摘要 (Executive Summary)

本報告針對臺灣原住民族語機器翻譯系統第三代版本（**v3**）之技術架構、資料前處理管線、訓練優化策略及系列消融實驗（Ablation Studies）進行完整技術回顧與量化分析。

相較於上一代模型（v2），v3 在架構層面透過 **Tokenizer Byte-Fallback 擴充機制** 根除長久以來的 `<unk>` 缺失，並重新構建 **42 語言粒度標記體系**；在資料層面引入 **全域嚴格防洩漏去重管線** 與 **語音/書寫大小寫正規化演算法**。實驗結果顯示：

1. **泛化能力顯著飛躍**：在嚴格排除訓練重疊的非可見測試集（`v2-unseen`）上，v3 族語→華語達到 **chrF 81.97 / BLEU 83.31**（較 v2 分別大幅提升 **+39.25 / +37.47**）；華語→族語達到 **chrF 55.84 / BLEU 30.83**（提升 **+8.38 / +8.70**）。先前的 v2 高分主要源於評測集嚴重污染（高達 90.5% 評測句落入訓練集記憶）。
2. **弱對齊外部語料（族語新聞）效益有限**：新聞語料之非逐句對齊特性易導致模型在「族語→華語」方向學會多譯與漏譯（chrF 下降 1.8）；僅在經嚴格過濾且單向應用於「華語→族語」段落翻譯時有邊際助益。
3. **無效擴充策略之收斂**：單詞表（Words）與人工拼接長句（Concat）未達預期效能，後者因風格偏移與長度分布失衡，反而拉低短句與未見測試集表現。
4. **多工詞素控制與跨語言表示遷移**：成功透過控制標記（`<seg>` 與 `<gloss>`）使單一模型具備詞素切分與詞素對齊輸出之能力；實驗同時證實 **多語言共享編碼表徵具有高度正向遷移效應**（移除其他語言後，族語→華語效能重挫超過 10 個 chrF 點數）。

## 2. v2 系統缺陷分析與 v3 架構改良方針

### 2.1 v2 核心痛點剖析
1. **Tokenizer 詞表限制與 `<unk>` 溢出**：
   - 原生 NLLB-200 詞表未開啟 Byte Fallback 機制。儘管未登錄字（OOV）僅佔資料總字元的 0.32%，但在華語測試與訓練集中，有高達 **23% 的句子** 出現 `<unk>`。
   - 典型問題包括常見漢字（如「蕉」、「猴」、「橘」）以及特定族語書寫符號（如阿美語喉塞音符號 `'`），導致資訊嚴重截斷。
2. **評測集污染與虛假高分 (Severe Data Leakage)**：
   - 深入診斷發現，v2 的評測集中有 13,978 句（佔比 90.47%）已存在於訓練集；`ithuan_formosan`（愛臺灣族語語料）與 `klokah`（族語E樂園教材）的 eval split 存在大量訓練交叉污染。v2 表面高分實為模型參數之過擬合記憶。
3. **推論退化與重複詞坍縮 (Repetition Collapse)**：
   - 族語表達中常見疊詞以示數量或強調（如 `fafoy, fafoy, fafoy`），v2 因過度去重而在解碼時坍縮為單一實詞（「豬」），語意複製保真度低。
4. **ASR 轉寫與書寫正則衝突**：
   - 阿美、布農、太魯閣/賽德克等語言習慣句首大寫，但大量的語音辨識（ASR）轉寫資料全為小寫，造成模型訓練時大小寫分布混亂。

## 3. v3 資料工程管線與訓練架構

```
[原始多源語料 (10 Data Sources)]
               │
               ▼
   [prepare_data.py 管線]
   ├── 品質過濾 (長度/無效標點/無效語言代碼)
   ├── 標點常規化 (句首去點 / 句尾統一為 . 或 。)
   ├── 語音與書寫大小寫正規化 (保留 ckv/xsy 區別性音位)
   ├── 段落整編 (以課文/段落維度劃分防跨語言滲透)
   ├── 合成疊詞對抗資料注入
   └── 嚴格雜湊去重與防污染分離 (~12 萬筆去重 / ~2.9k 筆評測隔離)
               │
               ▼
[擴充 Tokenizer (build_tokenizer.py)]
   ├── 42 語言專屬 Language Tokens (ami_Coas, pwn_Cent...)
   └── 256 個 Byte Tokens (全面啟動 Byte-Fallback)
               │
               ▼
[訓練架構: NLLB-200 600M Distilled]
   ├── BatchRebalanceSampler (長度聚合 + 4-GPU 運算量平衡)
   └── bf16 混合精度 / 10 Epochs / lr 1.5e-3 / 1.2M 雙向句對
```

### 3.1 訓練資料來源彙整
v3 整合 10 組核心平行語料庫，全數僅使用 `train` split，並建構為「族語→華語」與「華語→族語」之雙向訓練句對：

| 資料集識別代碼 | 中文名稱與內容說明 |
|---|---|
| `ithuan_formosan_text` | **愛臺灣族語文本**（族語自然文本） |
| `ILRDF/formosan_db` | **原語會族語影片字幕**（影音對齊字幕） |
| `ilrdf_dicts` | **原民會族語辭典例句**（辭典詞條釋義與例句） |
| `ntu_formosan_corpus` | **臺灣大學族語語料庫**（臺大學術採集調查語料） |
| `nchc_formosan` | **國網中心族語語料**（國網中心典藏語料） |
| `ithuan_formosan` | **愛臺灣族語語料**（通用會話與句子語料，另有獨立 eval split） |
| `nchu_pangcah` | **中興大學阿美語語料**（阿美語專門研究語料） |
| `formosan_bible` | **族語聖經語料**（宗教經典翻譯文本） |
| `klokah` | **族語E樂園教材**（數位學習教材文本，另有獨立 eval split） |
| `klokah_pcc` | **族語E樂園教材 PCC**（學習教材擴充語料） |

- **語言標籤設計**：採用語言別層級，涵蓋全臺 **42 個語言代碼**（如 `ami_Coas`、`pwn_Cent` 等），依序追加於 NLLB 原生詞表末端。
- **資料規模**：經前處理、除污與全域去重後，產出 **1,202,906 筆訓練句對**（v2 為 1,290,542 筆）。

### 3.2 資料處理管線規範 (`prepare_data.py`)
1. **語意品質篩選**：
   - 剔除空白、僅含純標點句子；過濾詞典純單字表（標籤包含 `word` 者），確保模型聚焦句子級語法結構；剔除無法精確映射至 42 個語言的無效代碼。
2. **標點正規化**：
   - 去除句首冗餘標點；句尾弱標點（逗號、冒號、頓號）依目標語系分別映射為族語半形句號 `.` 或華語全形句號 `。`。
3. **大小寫分流處理策略**：
   - **一般語言**：為對齊 ASR 轉寫小寫特性，訓練時統一將輸入句首降為小寫；推論時建立前置處理降小寫、後處理還原首字大寫機制。
   - **音位對立語言例外**：噶瑪蘭語（`ckv_Kava`）與賽夏語（`xsy_Sais`）之大小寫具備顯著音位（Phonemic）區隔，全流程嚴格保留原生大小寫，不進行大小寫轉換。
4. **防洩漏段落整合**：
   - `klokah`（族語E樂園教材）課文練習依華語句號重組為完整段落。同篇課文在 42 語言間的平行版本統一以華語為錨點整篇切出 10% 作為 eval，防止同篇課文語言 A 落在訓練集、語言 B 落在測試集的跨語言洩漏。
5. **重複詞合成增強**：
   - 自 `klokah`（族語E樂園教材）單詞表中抽取各語言單字，人工合成重複 2～6 次的字串（如「`fafoy, fafoy, fafoy`」對齊「豬、豬、豬」），強制打破解碼器的過度泛化去重偏差。
6. **全域除污與去重**：
   - 以 `(語言代碼, 正規化族語, 正規化華語)` 為雜湊鍵，徹底清除訓練集中與 eval 測試集完全相符或子句相符之資料（共剔除約 2,900 筆污染）； cross-dataset 去重剔除約 12 萬筆冗餘。修正前調查發現：
     - `ithuan_formosan`（愛臺灣族語語料）之 eval 約有一半出現在 `ithuan_formosan_text`（愛臺灣族語文本）與 `klokah`（族語E樂園教材）之訓練集中。
     - `nchu_pangcah`（中興大學阿美語語料）包含約半數 `klokah`（族語E樂園教材）阿美語（海岸）之 eval 句子。

### 3.3 Tokenizer 與語言標記設計 (`build_tokenizer.py`)
- **Byte-Fallback 實作**：於詞表後方擴充 256 個 Byte Token，保留原始 NLLB token ID 排序。當遇到未登錄字符時直接退化至 Byte 序列表示，達成 **`<unk>` 產生率 0.00%**。
- **42 語言精細控制標記**：擴充語言級別 Token（如 `ami_Coas`、`pwn_Cent`），使解碼器能依據特定語言之音韻與語法結構進行受控翻譯。

### 3.4 訓練參數與平行化調度
- **硬體環境**：4 × NVIDIA RTX A5000 (24GB VRAM)。
- **超參數配置**：
  - Base Model: `nllb-200-distilled-600M`
  - Optimizer / Precision: AdamW, bf16 混合精度
  - Learning Rate: `1.5e-3`（Cosine 排程，Warmup 10%）
  - Batch Size: 256 句 / global step（每 GPU 64 句）
  - Epochs: 10（訓練耗時約 11～12 小時）
  - Max Sequence Length: 512 tokens
- **批次重平衡取樣器 (`BatchRebalanceSampler`)**：
  - 依長度聚合序列，並按 token 計算複雜度等量均分至 4 張 GPU，將 padding 比例壓制至最低，消除分散式等待瓶頸。

## 4. 評測基準與指標體系

### 4.1 評測集切分規範
- **句子層級評測集 (`Sentence`)**：15,450 句，來源為 `klokah`（族語E樂園教材）與 `ithuan_formosan`（愛臺灣族語語料）乾淨驗證集。
- **未污染基準評測集 (`v2-unseen`)**：1,472 句，專門挑選自 `Sentence` 中 **v2 訓練期完全未接觸** 之真實未見句對，作為檢驗模型泛化能力之無偏差黃金標準。
- **段落層級評測集 (`Paragraph`)**：1,270 段，評估跨句上下文連貫性。

### 4.2 計分協議 (Scoring Protocol)
- **指標格式**：`chrF / BLEU`（解碼策略均採用 Greedy Decoding）。
- **切詞標準**：
  - 族語端：採用 `sacrebleu` 標準 `13a` 分詞器（基於空白與標點）。
  - 華語端：採用 `zh` 字元級分詞（Character-level Tokenization）。
- **前置正規化**：
  - 族語→華語計分前，統一將雙方標點轉為全形。
  - 計分預設不區分大小寫；唯 `ckv_Kava`（噶瑪蘭語）與 `xsy_Sais`（賽夏語）採大小寫敏感（Case-sensitive）評估。

## 5. 實驗結果與技術分析

### 5.1 基準對比：v2 vs. v3
各項指標對比如下表（**粗體**表示該指標最佳）：

| 評測維度 | v2 表現 (chrF / BLEU) | v3 表現 (chrF / BLEU) | 絕對差值 (Δ) |
|---|:---:|:---:|:---:|
| **句子 族語→華語** | 76.19 / 78.90 | **83.94 / 85.85** | **+7.75 / +6.95** |
| **句子 華語→族語** | **68.41 / 48.10** | 67.27 / 45.37 | −1.14 / −2.73 |
| **v2-unseen 族語→華語** | 42.72 / 45.84 | **81.97 / 83.31** | **+39.25 / +37.47** |
| **v2-unseen 華語→族語** | 47.46 / 22.13 | **55.84 / 30.83** | **+8.38 / +8.70** |
| **段落 族語→華語** | 9.69 / 8.66 | **12.85 / 13.14** | **+3.16 / +4.48** |
| **段落 華語→族語** | 33.61 / 5.28 | **39.40 / 9.54** | **+5.79 / +4.26** |

#### 技術分析
1. **記憶效應與泛化差距**：
   - 在整體 15,450 句的句子評測中，v2 在「華語→族語」略高，但其主因為評測集高達 90.5% 句子被 v2 訓練集覆蓋；一旦切換至完全未見的 `v2-unseen` 測試集，v2 分數崩跌至 BLEU 22.13，而 v3 保持在 30.83（**淨勝 +8.70**）。
2. **跨語言特徵抽取強化**：
   - 在 `v2-unseen` 族語→華語上，v3 展現爆發性成長（chrF +39.25 / BLEU +37.47）。除資料除污功勞外，主因在於 Byte-Fallback 消除 `<unk>`，使華語解碼端字元預測連貫性顯著提升。此外，該 1,472 句中有 1,206 句的華語端出現於 v3 訓練分佈中，驗證了單側目標語分佈對齊帶來的巨幅翻譯助益。
3. **段落建模能力初具雛形**：
   - 儘管段落絕對分數受限於注意力長度與對齊難度，v3 在雙向 BLEU 皆有顯著成長（華語→族語 BLEU 由 5.28 升至 9.54）。

---

### 5.2 弱對齊資料消融：族語新聞語料整合實驗
針對包含 4.3 萬筆平行文本的 `formosan_news`（**族語新聞語料**）進行注入實驗：
- **方案 A（新聞 篩選，單向）**：利用 v3 預先篩選族語與華語對齊度較高之語句，僅加入「華語→族語」方向，共 16,474 筆。
- **方案 B（新聞 不篩選，雙向）**：不作過濾，全量納入雙向訓練，共 43,724 筆。

| 評測維度 | v3 基準 | 新聞 (篩選，單向) | 新聞 (不篩選，雙向) |
|---|:---:|:---:|:---:|
| **句子 族語→華語** | **83.94 / 85.85** | 83.83 / 85.75 | 83.48 / 85.46 |
| **句子 華語→族語** | 67.27 / **45.37** | **67.33** / 45.23 | 67.13 / 44.71 |
| **v2-unseen 族語→華語** | **81.97 / 83.31** | 81.07 / 82.64 | 80.18 / 81.73 |
| **v2-unseen 華語→族語** | 55.84 / **30.83** | **55.92** / 29.72 | 55.80 / 29.58 |
| **段落 族語→華語** | **12.85 / 13.14** | 12.51 / 12.57 | 12.59 / 12.54 |
| **段落 華語→族語** | 39.40 / 9.54 | **40.09 / 10.14** | 39.87 / 9.38 |

#### 技術分析
1. **非對齊噪音傳遞**：新聞文本多為大意編譯，缺乏細粒度對稱結構。雙向全入使得「族語→華語」評測全面衰退，`v2-unseen` chrF 下降達 1.79。模型學會幻覺式產出與資訊過濾（多譯與漏譯）。
2. **單向篩選之局部效益**：篩選後單向加入華語→族語，段落 chrF 微幅上升 +0.69，BLEU 突破 10 大關；但對句子層級幾乎無統計顯著助益。
3. **架構決策**：不建議全量引入新聞語料；若考量段落多樣性，僅可保守應用高閾值過濾後之單向華語→族語資料。

---

### 5.3 結構與長度消融：詞彙注入 vs. 串接段落
- **詞彙組（Words）**：回補 `klokah`（族語E樂園教材）單詞表（`*_word`，共 156,360 筆雙向單字對）。
- **串接段落組（Concat）**：依 ID 連續性將同一文件中 2～4 句相鄰句子強制拼合成一筆段落（117,720 筆雙向句對），試圖迫使模型學習長跨度依賴。

| 評測維度 | v3 基準 | 詞彙組 (Words) | 串接段落組 (Concat) |
|---|:---:|:---:|:---:|
| **句子 族語→華語** | **83.94 / 85.85** | 83.70 / 85.67 | 82.69 / 84.71 |
| **句子 華語→族語** | **67.27 / 45.37** | 66.89 / 44.93 | 66.75 / 44.82 |
| **v2-unseen 族語→華語** | **81.97 / 83.31** | 81.50 / 82.85 | 79.13 / 80.74 |
| **v2-unseen 華語→族語** | **55.84 / 30.83** | 55.41 / 30.01 | 55.59 / 30.47 |
| **段落 族語→華語** | **12.85 / 13.14** | 12.54 / 12.77 | 12.42 / 12.39 |
| **段落 華語→族語** | 39.40 / **9.54** | **39.50** / 9.47 | 39.20 / 9.00 |

#### 技術分析
1. **詞彙獨立映射之副效應**：單純詞彙對缺乏語法引導，加入後反而損害解碼器對於連貫語法的平滑估計，導致句子指標全面下挫 0.2～0.5。
2. **長度拼接之分布失真**：
   - 串接段落並未提振段落評測（段落族語→華語反而自 12.85 降至 12.42），且嚴重傷害短句評測（`v2-unseen` 族語→華語重挫 −2.84 / −2.57）。
   - 歸因分析：`ILRDF/formosan_db`（原語會族語影片字幕）等資料在串接時以逗號硬性拼接，造成標點形態與標準段落文體偏離；同時長句霸佔 self-attention 計算步數，稀釋了短句梯度更新權重。兩者均不予採用。

### 5.4 形態語法多工控制：11 語言標注語料消融實驗
本實驗引入具備語言學切分之標注資料集（`corpus_20260924.yaml`，共 4,292 句），探討詞素切分（`<seg>`）與逐詞註解（`<gloss>`）對常規翻譯之交互影響。  
為提升標注佔比，實驗收斂至 **11 個目標語言**（阿美 3 語言、排灣 3 語言、布農 2 語言、太魯閣、魯凱、泰雅各 1 語言），訓練集為 51.9 萬至 54.5 萬筆，評測集同步限制於此 11 語言（句子 4,329 句、段落 349 段）。

#### 實驗分組設計
- **組別 c (Control)**：基準組，純常規平行句對（519,366 筆）。
- **組別 b**：組別 c ＋ [族語原句 ↔ 華語]（佔比 1.6%）。

#### 深度技術洞察
1. **常規翻譯與詞素多工之正交性**：
   - 在 11 語言範圍內，無標注的純淨組別 c 在各項常規翻譯指標上均奪得最高分。加入 b、a、d 後，chrF 下降 0.1～0.8，BLEU 下降 0.2～1.2。顯示在小樣本條件下，詞素切分訊號並未對宏觀句子翻譯產生直接正向正則化效果。
2. **受控條件格式生成能力驗證**：
   - 組別 d 在加入特殊指示 token 後，成功學會條件分支生成：給定 `<seg>` 輸出帶有 `-` 與 `=` 之形態邊界切分；給定 `<gloss>` 輸出對應語法詞素對齊。儘管目前生成細緻度仍有欠缺（偶發漏譯或退化為一般中文），但已確立單一序列模型相容多工語言學結構分析之可行性。
3. **跨語言共享表示的關鍵作用 (Cross-Language Representations)**：
   - 比較「全資料 v3」與「組別 c」：當訓練集從全 42 語言限縮至 11 語言時，**族語→華語巨幅滑落 10.23 個 chrF 點數**（84.93 → 74.70）；針對華語未登錄訓練集之句子，表現更是自 59.56 崩跌至 50.25。
   - 此現象直接證實：南島語族各語言間具有深層語法與構詞共性，透過 NLLB 統一架構聯合訓練，模型習得高泛化性的底層族語語意表徵，各語言間的遷移學習對翻譯效能至關重要。
4. **評測盲區與未來校準**：
   - 目前評測集均為常規自然語言文本，缺乏詞素層級之 Golden Standard；且標注語料全數投入訓練，無法客觀評估形態切分本身的準確率。未來必須預留專屬驗證集以實現量化驗證。

## 6. 技術結論與後續演進路徑

### 6.1 核心結論
1. **v3 確立為生產部署之新基準線**：徹底排除了評測集污染，並解決了 23% 華語句子之 `<unk>` 截斷異常，在真實未知語意情境展現卓越穩健性。
2. **語料品質重於規模盲目擴張**：弱對齊新聞語料、離散單詞與人工強行拼接段落，均對整體模型幾何收斂造成負面干擾，確立後續應優先推動高品質、高精度句對之構建。
3. **多語言聯合建模為必要架構**：不可輕易採用「單一語言獨立微調」策略，全語言聯合表徵學習是支撐低資源語言泛化性之核心支柱。

### 6.2 2026 Q4 ~ 2027 Q1 後續研發路徑 (Next Steps)
- **詞素多工專屬評測集建立**：保留至少 10% 形態標注語料作為獨立 Eval，正式建立形態切分與詞素翻譯之 F1-score / BLEU 評測規約。
- **高閾值過濾與對齊增強 (Quality Estimation & Alignment)**：開發針對族語新聞與廣播語料之神經語義對齊過濾器（利用單詞對齊或語意相似度模型），僅保留餘弦相似度大於閾值之片語。
- **長文本解碼優化**：針對段落翻譯，設計階層式上下文編碼（Context-aware NMT）或滑動視窗解碼，擺脫目前純依靠短句自回歸生成帶來的長文本退化問題。
- **模型輕量化與推論最佳化**：評估 INT8 / AWQ 量化方案，優化推論階段前置小寫化與後置大寫還原之管線延遲，以支援族語即時轉譯服務。
